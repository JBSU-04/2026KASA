# 점유 지도 기반 정적 장애물 회피

대회 런치의 정적 장애물 구간(M2, 0.csv idx 2400–3700)과 음영구간(M8,
3.csv idx 7000–9000)의 정적 회피 경로를 생성한다. 다른 미션의 경로와 동적
장애물 정지 판단은 기존 노드가 담당한다. MPC 설정은 변경하지 않는다.
대회 기본은 `obstacle_avoidance_node` 내부 라이브러리 방식이다. 최종 경로·실패·
속도 출력은 이 기존 노드만 발행한다. 독립 엔진 노드를 함께 실행하지 않는다.
0.csv idx 2100부터 점유 누적과 후보 계산을 준비하고, 최종 경로 채택은 기존 미션
구간·신호등·동적 hold·터널 관측 가드를 통과해야 한다. idx 2400 이전 후보는
진단용이며 기준경로 출력을 대체하지 않는다.

## 내장 방식과 복구

`roslaunch total_bringup competition.launch avoidance_backend:=occupancy`가 기본이다.
`avoidance_backend:=frenet`은 보존한 기존 방식으로 명시적으로 복구한다.
점유 엔진 실패 시 자동으로 Frenet 경로를 선택하지 않는다. 최근 0.3초 이내의
이전 유효 경로를 최신 점유/연석/현재 자세로 재검사할 수 있는 동안만 유지하고,
그 외에는 기존 실패·정지 출력을 사용한다.

점유 엔진 설정은 `config/avoidance.yaml`이며 런타임 네임스페이스는
`/obstacle_avoidance_node/embedded_engine`이다. 회피 시작 코리도는 반폭 1.3m,
전방 30m이다. 충돌 검사용 점유 지도는 이 코리도로 잘라내지 않는다.
기존 `/speed_limit/avoidance_mps`가 회피 목표 속도의 출처이고 MPC 설정은 유지한다.

내장 모드에서는 기존 ID에 연결 성분의 큰 사각형을 덮어쓰지 않는다.
`/occupancy_avoidance/obstacles`의 사각형은 진단용이며 실제 계획·검사는
`occupied_cells_world` 및 내부 정적/현재 점유 셀을 사용한다. RViz의
`/occupancy_avoidance/markers`가 실제 점유와 연석 중심 제한을 표시한다.
`/obstacle_avoidance/selection_state`와 `/obstacle_avoidance/validation_debug`는
실제 최종 선택의 plan_id, geometry_stamp/digest, 거부 이유, 속도 상한을 기록한다.
후보 토픽은 진단용이며 최종 `/local_path`가 실제 연결·검사를 통과한 경로다.

QP 탐색은 별도 작업 큐의 계획 스냅샷으로 계산한다. 스냅샷 계산 결과는
새 원시 스캔으로 최신 형상에서 다시 검사하고, 형상 누적을 과거 스냅샷으로
되돌리지 않는다. 후진 인계도 현재 상태에서 연결·차체 검사를 통과하고 기존
최종 노드가 경로를 발행한 뒤에만 `forward_owner_ready`를 응답한다.
터널 배경 점맵/새 점 선감속/동적 판단·벽 헤딩 보정 노드는 계속 기존 구성이다.

## 파이프라인

1. 기존 GroundGrid가 생성한 중력 보정 원시 점군과 지면 표본을 받는다.
2. 측정 시각의 odom을 보간하여 점을 지역 좌표의 OctoMap에 누적한다.
   UTM 좌표 연산은 double을 사용한다.
3. 독립적인 세 스캔에서 반복 관측된 표면은 정적 점유로 유지한다.
   같은 높이의 실제 반환 광선으로 세 번 비어 있음을 확인해야 삭제한다.
   가려졌다는 이유만으로 정적 표면을 줄이거나 지우지 않는다.
   확인된 동적 트랙은 영구 정적 누적에서 제외한다.
4. 실제 연석 경계에서 차량 반폭 0.95m + 연석 여유 0.10m = 1.05m를
   도로 안쪽으로 이동시킨 차량 중심 경계를 만든다. 고정 경계는
   `new_lane/config/curb_edges.yaml`, 터널 경계는 `tunnel_wall_profile.yaml`이다.
   신선한 `/tunnel/wall_limits` 측정은 해당 주변의 터널 경계를 대체한다.
5. 차량 전체 외곽과 점유 셀을 검사하며 연결된 좌우 통로를 탐색한다.
   연석 중심 경계는 탐색과 최적화의 제약으로 모두 사용한다.
   최적화 이후 단순히 연석 침범 경로를 탈락시키는 방식에 의존하지 않는다.
6. Apollo 원본 Piecewise Jerk와 OSQP로 횡방향 위치·기울기·곡률 변화가
   매끄러운 경로를 최적화한다. 시작 상태에 현재 차량의 방향과 측정 곡률을
   반영한다. 연속 다항식을 0.1m 간격으로 평가한다.
7. 경로를 0.15m 간격으로 다시 검사하여 차량 외곽의 충돌과 연석 침범을
   확인한다. 유효한 기존 경로는 유지하고 새 점유가 이를 막으면 다시 생성한다.
   신선한 입력이 없거나 안전한 경로가 없으면 빈 경로, 실패, 속도 0을 출력한다.

회피 대상의 미통과 점유를 가로지르지 않고 차체가 기준경로로 연결될 수 있으면,
기존 new_lane의 공간 5차식 복귀를 별도 단계로 사용한다. 현재 횡위치·방향·곡률에서
끝점 횡위치·기울기·곡률 0으로 연결한다. 시간 기반 식을 사용하지 않으므로 정지
상태에서도 경로점 간격이 사라지지 않는다. 길이 계산은 기존 공간 복귀와 동일하게
횡가속 1.5m/s², 저크 8m/s³, 계산 속도 하한 4.5m/s, 길이 6~32m를 사용한다.
초기 상태까지 포함한 다항식 미분 및 실제 차체/연석 검사를 통과해야 채택한다.

채택한 복귀 곡선은 월드 좌표로 유지하고 주행한 부분만 잘라 사용한다.
복귀 중 새 점유가 경로를 막으면 연결 통로 회피를 다시 판단한다.
직접 복귀 후보가 실패해도 기존 회피 경로가 유효하면 유지한다.
인지 목록이 비어 있다는 이유만으로 복귀를 시작하지 않는다.
`spatial_return_to_reference`, `held_spatial_return`, `reference_passthrough`로
직접 복귀·복귀 곡선 유지·기준경로 인계를 구분한다.

`spatial_return_max_lat_accel`, `spatial_return_max_lat_jerk`,
`spatial_return_min_speed`, `spatial_return_min_transition_m`,
`spatial_return_max_transition_m`에서 복귀 형상을 조절한다.
`return_min_distance_m`(12m), `return_min_time_sec`(2초)은 복귀 후보를 시도하기
전에 확인할 기준경로의 빈 구간 길이를 정한다. `return_center_weight`는 다음
장애물이 있는 회피 계획의 빈 구간 목표에 쓰이며 직접 복귀의 모양을 정하지 않는다.
매초 복귀를 다시 최적화하던 `return_replan_period_sec`는 제거했다.

복귀 완료는 실제 횡오차 0.15m, 방향 오차 3도, 앞 8m 계획 오프셋 0.20m 이내와
앞 기준경로의 차체 통과 가능 조건이 0.5초 유지될 때 판단한다. 이후 회피 엔진의
추가 속도 상한은 9999(해제)로 보내고 기존 MPC/미션 속도 제한이 주행 속도를 정한다.
회피 중 속도 상한은 위치별 곡률과 감속거리로 계산한다. 정상 기준경로의 먼 곡률이
추가 회피 속도 상한으로 계속 남지 않도록 한다.

터널 실측 벽 직선은 전방 6m 이내이고 기준경로 방향과 벽 방향 차이가 5도 미만인
구간에서만 적용한다. 먼 곡선 구간은 실측 프로파일과 실제 점유 표면을 사용한다.
GroundGrid 지면 표본은 원시 스캔 시각의 센서 좌표로 정렬하고 위치별 지면을 추정한다.
지역 지면 추정이 기존 평면보다 낮아져 가짜 장애물 점을 만드는 것은 허용하지 않는다.
최소 장애물 높이 0.06m 및 차체/연석 충돌 검사는 그대로다.

연석에 일반 장애물 여유 0.20m를 추가하지 않는다. 차량 중심 경계에는
1.05m를 적용하고 실제 차체 모서리에는 물리적 연석 경계만 적용한다.
차량 반폭을 모서리에 다시 더해 이중으로 제한하지 않는다.

## 첫 장애물 접근 계획

`static_planning_start_idx`(2100)부터 후보를 사전 계산한다.
기존 노드가 최종 경로의 유일한 발행자이고 미션 시작 인덱스는 바꾸지 않는다. 특정 장애물 좌표, 장애물 인덱스 또는
회피 방향을 넣지 않는다. 이것은 고정된 미션 접근 구간의 시작점이다.
장애물이 없으면 기준경로를 출력한다. 첫 신호 정지선 idx 2021 및 신호등
정지 판단과 MPC 피팅은 유지한다.

접근 단계(idx 2100~2399)의 `approach_horizon_m`은 50m다. 제공되는 기준경로
길이에 따라 실제 약 49m로 잘릴 수 있다. `map_length_m`(80m)으로 전방 점유
범위 60m를 확보하여 차량 앞부분까지 검사한다. 본 정적 구간과 M8의
`horizon_m`은 40m로, 이전의 실효 계획 길이(40개 1m 구간)를 유지한다.
두 번째 장애물의 회피 비용, 곡률, 횡가속과 공간 복귀 설정은 바꾸지 않는다.

접근 마진 `approach_obstacle_margin_m`은 일반 마진과 같은 0.20m다.
저장된 점유 크기는 변경하지 않고, 회피 시작 관련성은 아래 승인 조건으로 판단한다.

접근 단계에서는 유지 경로가 현재 계획 길이보다 5m 이상 짧아지기 전에
먼 구간을 다시 계획한다. 두 번째 장애물과 M8의 기존 경로 유지 기준은
그대로다. 먼 위치에서 연결 통로가 막혔지만 충분히 긴 가까운 구간이
검증되면 `approach_safe_prefix_*` 경로를 사용하고 남은 검증 거리에 맞춰
감속한다. 가까운 충돌, 짧은 가용 경로 또는 동역학 실패는 승인하지 않는다.
`planning_horizon_m`, `static_approach`, `approach_blockage_distance_m`과
`speed_limit_reason=approach_visible_coverage`로 구분한다.

## 설정과 시각화

`config/avoidance.yaml`에서 반폭, 연석 여유, 장애물 여유, 점유 해상도,
최소 높이, 목표 회피 속도와 곡률/횡가속 제한을 변경한다.
목표 회피 속도는 8.333m/s(30km/h)이다. 경로 곡률, 기존 MPC,
미션 속도 제한과 정지 신호에 따라 실제 속도는 낮아질 수 있다.

RViz의 `/occupancy_avoidance/markers`:

- 빨강 셀: 반복 관측된 정적 점유, 주황 셀: 아직 일시적인 점유.
- 청록 선: 물리적 연석, 노랑 선: 차량 중심 제한 경계.
- 초록 선: 선택된 연결 통로, 파랑 사각형: 경로상의 실제 차량 외곽.

대회 RViz에는 `/perception/reference_corridor`도 기본으로 표시한다.
자홍색 경계와 반투명 띠는 인지 노드가 사용하는 원본 `/final_waypoint` 기준
코리도이며, 실제 `path_corridor_half_width` 값(현재 1.7m)을 읽는다.
회피 경로의 파란 차량 외곽이나 초록 연결 통로와 다르다. ego 전방 보조 코리도와
점유 엔진 전체 입력 범위를 나타내지는 않는다. 경로 만료 또는 미션 비활성 시 삭제한다.

이는 클러스터 박스를 고정 크기로 늘린 결과가 아니다. 가려진 실제 표면은
유지하지만 처음 보지 못한 면의 정확한 크기는 LiDAR만으로 복원할 수 없다.
처음 관측되는 면은 새 점유로 추가되고 기존 경로를 재검사한다.
관측하지 못한 공간 전체를 안전한 공간으로 인증하는 기능은 없다.

`return_rejection_reason`은 직접 복귀가 거부된 이유(`occupancy`, `curvature`,
`return_dynamics`, `insufficient_return_horizon`)를 남긴다. `not_requested`는
빈 기준경로 구간 또는 현재 복귀 상태 조건이 충족되지 않아 시도하지 않았다는 뜻이다.
`none`은 직접 복귀·유지 또는 기준경로 인계가 승인되었다는 뜻이다.

진단 JSON은 `/obstacle_avoidance/validation_debug`의
`engine`, `reason`, `held`, `compute_ms`, `static_voxels`, `max_curvature`를 본다.
`motion_state`는 CRUISE/APPROACH/AVOIDING/RETURNING/STOP,
`speed_limit_reason`은 실제 발행한 속도 상한의 출처다. `boundary_source`와
`failure_distance_m`으로 제한 경계 및 최초 연결 실패 위치를 확인한다.

## 빌드와 오프라인 검증

```bash
cd /home/kuuve/catkin_ws
catkin_make -j4
catkin_make run_tests_occupancy_avoidance -j4
```

`scripts/export_bag.py --help`에서 원시 점군, odom, 기준 경로를 동기화하는
내보내기 방법을 확인한다. 내보낸 파일은 아래처럼 평가한다.

```bash
devel/lib/occupancy_avoidance/occupancy_offline frames.bin metrics.json
```

이 실행 파일은 ROS master, 토픽 발행, 차량 제어 소켓을 사용하지 않는다.
OCC2 파일에는 기록된 GroundGrid 지면, 벽 제한과 동적 트랙 제외 영역을 함께 넣는다.
지면 표본은 pose 보간으로 원시 점군 시각에 정렬한다. OCC1 형식도 읽을 수 있지만
지면/벽/동적 제외 데이터가 없어 온라인 입력을 완전히 재현한 결과는 아니다.
백에 지면 토픽이 없으면 예상 지면 높이의 원시 표본으로 지면 평면을 추정한다.
기록된 odom에서 계산하므로 새 경로를 따라간 폐루프 주행도 검증하지 않는다.

최근 세 주행의 평가 결과와 한계는
`analysis/occupancy_avoidance_20261004/validation.md`에 기록한다.
음영구간의 실제 주행 재검증은 별도로 필요하다.
공간 복귀 분리와 기준경로 인지 코리도 추가 검증은
`analysis/occupancy_spatial_return_20261004/validation.md`에 기록한다.
첫 접근 계획을 앞당긴 검증은
`analysis/occupancy_early_first_20261004/validation.md`에 기록한다.

## 실행과 복구

`new_lane/launch/obstacle_avoidance.launch`의 `occupancy_engine`은 기본 true다.
기존 노드는 이 엔진이 소유하는 구간에서 경로와 회피 속도를 중복 발행하지 않는다.
대회 런치를 재시작해야 새 실행 파일과 설정이 적용된다.

기존 방식으로 복구할 때는 위 런치의 `occupancy_engine` 기본값을 false로
바꾸고 전체 런치를 다시 시작한다. 실행 중 한 노드의 파라미터만 바꾸면
경로 발행 주체가 겹칠 수 있으므로 이 방법을 사용하지 않는다.
수정 전 기존 파일은 `backups/occupancy_avoidance_20261004/`에 보관했다.

## 기준경로 코리도와 회피 승인 (2026-10-05)

M2 접근/M2 및 M8에 `trigger_corridor_half_width_m=1.5`,
`trigger_distance_m=30`, `trigger_hold_sec=3`를 적용한다. 원본 기준경로와
관측 점유 셀의 가장자리를 검사한다. 코리도 밖·30m 밖 점도 삭제하지 않으며
전체 회피 후보의 차체 충돌 검사에 사용한다. 미확인 점은 충돌 검사에 즉시
반영하지만 신규 조향을 시작하지 않는다. 독립 3회 관측 확인 조건은 그대로다.
거리 조건이나 승인 전환으로 점유를 자르거나 초기화하지 않는다.

대상 누락 시 마지막 실제 관측부터 최대 3초 유지한다. 주변 충돌 전용 점이나
미관측 고정 셀로 유지 시간을 갱신하지 않는다. 차량 후미를 완전히 지난
대상은 해제한다. 이미 시작된 회피/복귀는 기존 안전 경로 유지와 복귀 검사를
사용한다. 회피 시작 대상이 없을 때는 검증된 기준경로를 출력한다. 전방 점유로
전체 기준경로가 불가능하면 안전한 접두 경로와 정지 가능한 속도 상한을 사용한다.
바로 앞 차체 충돌은 승인 조건과 무관하게 정지한다.

M2 신호 판단은 `/localization/stop_ahead`, `/localization/stop_required`를
각각 0.7초 신선도로 확인한다. 전방 80m 이내 정지 신호에서 후보의 기준경로
정렬 완료 후 12m 검증 꼬리를 확보할 수 있고, 그 완료 거리가 신호 정지 목표
이전일 때만 신규 회피를 허용한다. 정지 목표는 신호 미션의 전축 오프셋과
정지 버퍼를 공유한다. 후보 지평 안에 완료가 확인되지 않으면 보류한다.
보류 시 침범 정도에 따라 장애물 앞 10~20m 대기 거리, 감속 1.5m/s²를 사용한다.
입력 만료로 승인하지 않는다. 이미 물리적으로 경로에서 벗어나 있는 차량은
경로를 갑자기 되돌리지 않는다. 신호 정지와 충돌 방지는 계속 우선된다.
M8에는 신호 미션이 없으므로 신호 시작 제한/속도 상한을 적용하지 않는다.

M2는 단발성 속도 오판으로 정적 점유를 삭제하지 않는다. M8은 최신
`/obstacle_stop/dynamic_state`의 dynamic_ids/static_ids를 우선 사용한다.
0.5초 넘은 상태는 제외 근거로 유지하지 않고, 유효한 움직임과 2회 연속 동적
판정이 있는 트래커로 폴백한다. 움직임 영역 제거는 기존 엔진 방법을 사용한다.

RViz의 `/occupancy_avoidance/markers`에 자홍색 `static_start_corridor`와
30m 끝, 신호 정지 목표/복귀 완료 점, 승인 상태를 추가했다. 점 수집 폭과
생성된 회피 통로는 시작 코리도와 별개의 설정이다.
오프라인 OCC3 입력은 신호/동적 상태와 평가 시각을 포함한다. OCC1/2 입력도
읽지만 신호 검증에는 사용할 수 없다. `--verify-geometry`는 승인 조건을 끈
별도 엔진과 같은 입력을 처리해 3D 점유 및 확인/제거 이력의 해시를 비교한다. `--disable-trigger`는 승인 비교용이며
신호 로직이나 점유 저장을 끄지 않는다.

검증: `analysis/occupancy_trigger_20261005/validation.md`.


## 내장 엔진 원거리 회피 시작 보완 (2026-10-05 20:01 백)

기존 `/obstacle_info`의 `static_occupancy` 폴리곤을 시작 인증 입력으로도 받는다.
16채널 원거리 표본이 서로 다른 셀에 찍혀도 기존 물체 단위 확인 결과로 회피를 시작한다.
시작 코리도 반폭1.3m/전방30m와 마지막 실제 관측3초 조건은 유지한다.
통과/배경/동적 물체를 제외하며 M8은 정적 분류도 요구한다.
이 폴리곤은 시작 승인용이고 충돌 점유를 칠하거나 기존 점유 크기를 변경하지 않는다.
원시 셀의 독립3회 확인, 충돌 검사, 신호 hold, 터널 가드는 유지된다.
첫 라이다 전에는 `waiting_lidar`로 대기한다.
OCC4는 기존 인증 폴리곤을 추가하며 OCC1/2/3도 읽는다.
`--disable-certified-admission`으로 연결 전후를 비교할 수 있다.
검증: `analysis/static_2001/report.md`.
