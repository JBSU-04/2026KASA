# 회전교차로 차량 보존과 출발 예측

대회 설정은 `config/sites/kcity_roundabout_utm.yaml`이며 로컬 좌표 설정에도
동일한 인지·추적 파라미터가 적용된다.

## 2026-10-01 21시대 3주행: 시설물 ROI와 틈 유지 보완

분석 대상은 `competition_2026-10-01-21-26-55.bag`, `21-27-56.bag`,
`21-28-52.bag`다. 실제 순환 차량 중심 반경은 16.2~19.7m였지만,
출구에서 선행차로 선택된 표지판은 14.5~15.3m였다. 표지판 중심점의
작은 이동 때문에 `has_moved`까지 켜져 이동 여부만으로 구분할 수 없었다.

- `roundabout/vehicle_roi`는 차량 중심 전용 반경 15.8~20.5m다.
  점군은 `point_padding: 1.2`m로 차체 측면을 보존하고, 클러스터 중심과
  추적 출력에서 다시 중심 ROI를 검사한다. 자차 상태 전환용 기존
  `radius/inner: 14.5`, `outer: 21.5`와 분리한다. RViz의
  `roundabout_vehicle_roi` 청록색 원 두 개로 경계를 볼 수 있다.
- EXIT 선행차는 남은 원호가 아니라 현재 출구 경로의 앞쪽 투영 위치와
  횡거리 2m 이내인지 검사한다. 실제 경로 앞 정지 차량은 제외하지 않는다.
- 이미 이동 확인된 차량은 검출 면 변경으로 새 속도 관측을 얻지 못해도
  마지막 유효 근거를 최대 0.6초만 유지한다. 정지 관측은 즉시 반영하고,
  근거가 오래되면 유효성을 내린다. 오래된 차량을 시설물로 무시하거나
  빈 틈으로 만들지 않고, 속도 미확정 차량으로 계속 판단에 남긴다.
- 실제 ACC 시간간격 상한을 예측할 때 앞차 속도로 자차 최대 속도를
  미리 고정하는 중복 감속 제한은 적용하지 않는다. 실제 ACC 설정은
  변경하지 않았다. 정지 상태에서는 같은 틈의 출발 시각도 탐색한다.
- 앞차가 아직 상류에 있으면 일시적인 불가 예측 0.3초만으로 틈을
  버리지 않는다. 앞차가 합류점에 도달하거나 뒤차가 이미 지나갔을 때
  다음 틈으로 넘어갈 수 있다. 이는 틈 유지일 뿐 출발 승인이 아니며,
  앞뒤 거리/TTC, 의무정지, COMMIT ID 고정과 취소 제동은 유지한다.

`replay_roundabout_bag`는 ROS 제어 명령을 발행하지 않는 코어 입력 재평가다.
표지판이 ROI 밖인 선행차 선택은 두 백에서 각각 84/109프레임이었고,
수정 코어의 재평가에서는 모두 0이었다. 차량 중심 범위는 기존 추적 출력으로
측정했으며, 새 ROI를 통한 원시 점군 재검출 성능을 보장하는 수치는 아니다.

진입은 고정된 기록 궤적으로 더 빨라졌다고 결론 내릴 수 없다. 기본 재평가는
과거의 속도 유효성 누락을 그대로 사용한다. `--velocity-hold`는 과거 유효성
플래그로 0.6초 보완을 근사하며, 실제 트래커 내부 근거 시각은 재현하지 않는다.
이 근사 재평가에서 21:26 백은 GO가 나오지 않았고, 나머지는 최초 GO가
21.67/22.39초였다. 기록 자차가 이미 움직인 이후의 승인도 포함하므로
진입 개선의 증거로 쓰면 안 된다. 실제 ACC 4m/1.5초 및 감속 앞차 아래에서
여전히 보수적인 대기가 남는다. 안전 기준을 더 낮추지 않았으며 새 주행에서
진입 성공·대기 시간과 추적 유지 여부를 확인해야 한다.

미션/트래커 노드 빌드와 관련 단위 테스트 97개를 통과했다.
적용하려면 회전교차로 미션과 LiDAR 트래커를 모두 재시작해야 한다.

## 차량 검출 및 보존

- 차량 후보 상한은 길이 14 m, 높이 4.5 m다. 폭과 낮은 선형 구조물 필터,
  원형 차로 ROI, 실제 이동 확인 조건은 유지한다.
- `lidar_tracker/tracking/confirmed_hold_seconds: 3.0`은 마지막 실제 검출부터
  이동·속도 확인 차량을 보존하는 시간이다. 원 궤도로 위치와 접선 속도를
  예측하며, 재검출 시 예측 위치와 연계해 같은 ID를 유지한다.
- `retained_confidence_floor: 0.45`는 보존된 차량이 미션 신뢰도 필터에서
  조기에 빠지는 것을 막는다. 측정 횟수는 예측으로 증가하지 않는다.
- 확인 차량은 해당 ID에서 관측한 최대 차체 길이를 유지한다. 부분 검출에
  부분 검출의 중심 위치 변화도 예측 위치 쪽으로 완화한다.
  나머지 크기 축소는 `confirmed_size_shrink_alpha: 0.02`로 완화한다.
- 미검출 동안 점유 길이에 0.5 m/s, 최대 1.5 m의 여유를 추가한다.
- 합류점에 접근하거나 점유 중인 차량의 보존 만료 뒤 `expiry_guard_seconds: 1.0` 동안 트래커 유효성을 낮춰 즉시
  빈 교차로라고 승인하지 않는다. 이미 합류점을 벗어난 차량의 만료는
  다른 틈의 진입을 막지 않는다. 센서 무수신 시에는 기존 타임아웃이 적용된다.
- RViz 트래커 박스의 파란색 `PRED ...s`는 실제 재검출이 아닌 예측 보존이다.
  보존은 유한하며, 3초를 넘는 가림을 계속 추적한다는 의미는 아니다.

## 출발 예측

MPC는 `/control_feedback/curvature_capacity_speed_mps`로 정지 출발 램프를
제외한 현재 경로의 곡률 허용 속도를 추가 출력한다. 기존 제어 속도 제한,
곡률 필터, 비용 가중치와 피팅은 변경하지 않는다.

미션은 현재 자차 속도에서 기존 MPC 미션 가속 램프와 회전교차로 예측 가속도
중 작은 값으로 가속해 도달 시간을 계산한다. 정지 당시 미션 목표 속도를
미래 내내 고정하지 않는다. 곡률·미션 피드백이 오래되면 진입을 보류한다.

앞차의 차체 뒤끝이 충돌점을 비우는 시각에 맞춰 출발하며, 가까운 앞차 조건과
뒤차 점유 간격·TTC 검사를 유지한다. `gap_select/max_wait` 밖의 먼 틈은
승인하거나 뒤차 위험으로 분류하지 않고 같은 목표를 재평가한다.

새 피드백 연결을 위해 MPC·트래커·미션 노드를 함께 재시작해야 한다.
빌드 및 단위 테스트와 실제 주행 검증은 별개이며, 이 변경에서는 백 재생을
실행하지 않았다.


## 회전차량 속도 추정 보완 (2026-09-30)

`roundabout/gap_select/use_tracker_velocity: true`에서 미션의 추가 위치 회귀를
사용하지 않는다. 트래커는 실제 검출의 중심각만 사용하고, 가림 보존 중의
예측 위치와 부분 검출 위치 필터에 섞인 예측값을 속도 관측으로 사용하지 않는다.
중복·역순 센서 타임스탬프도 관측 수에 추가하지 않는다.

대회 트래커는 `robust_circular_velocity: true`, `velocity_window_seconds: 1.8`,
`velocity_window_size: 20`, `velocity_pair_min_span: 0.6`, `velocity_min_span: 0.3`,
`velocity_alpha: 0.25`다. 충분한 시간 간격을 둔 관측 쌍들의 각속도 중앙값으로
중심점 잡음과 순간 튐을 완화한다. 초기에는 확보한 관측 길이에 맞춰 쌍 간격을
줄인다. 최근 0.25초 이상의 실제 관측이 0.1m 이내에 머물면 정지를 빠르게
반영하므로 긴 창 때문에 정지한 차량을 계속 이동으로 보지 않도록 한다.

미션은 각속도를 기준 원호 거리와 동일한 좌표로 환산해 TTC를 계산한다.
앞차·뒤차가 동일한 추정원을 사용하고 기존 `speed_margin` 여유는 유지한다.
ACC와 RViz의 기본 m/s 표시는 물리 속도를 사용하며, RViz `arc`는 계산용
원호 속도다. 기존 `speed_window`, `speed_min_span`, `speed_disagreement_limit`은
`use_tracker_velocity: false`인 이전 미션 회귀에서만 사용한다.

20km/h는 백 분석의 비교 기준이며, 런타임 속도를 20km/h로 고정하지 않는다.
NPC의 실제 감속 가능성과 위치 관측 오차는 별개이며, 보완 후 실제 성능은
새 주행에서 확인해야 한다. MPC 피팅과 진입 조건은 이 변경에서 조정하지 않는다.

## 2026-10-01: 출발 승인과 진입 예측 일치

순차 판단은 틈 예약(`feasible`)과 지금 출발 가능(`departure_ready`)을 분리한다.
대기시간이 남아 있으면 예약한 틈을 유지하며 기다린다. 기존 `seq_go_tolerance`는
설정 호환을 위해 읽지만, 남은 대기시간을 빌려 조기 출발하는 데 사용하지 않는다.

대기와 COMMIT에서 동일한 0.02초 간격 자차 예측을 사용한다. MPC 가속 제한,
앞차 속도 상한, 앞차 통과 전 정지거리 제동 상한과 재출발을 반영한다.
앞차 범퍼 간격은 `standstill_gap + front_headway * 자차속도`를 검사하고,
뒤차에는 `seq_rear_headway`, `ttc_rear`, `late_margin`을 적용한다.
COMMIT에서는 현재 속도를 그대로 이어 쓰며 순간적으로 정지 위치로 옮겨 계산하지 않는다.
MPC 예측 모드에서는 속도캡 변환기의 ACC 제동·시간간격 상한도 반영한다.
기본값은 고정 간격 4m, 시간 간격 1.5초이며, 실제
`/constraint_to_speed_cap/lead_standstill_dist`, `lead_time_gap` 파라미터가
있으면 해당 값을 읽는다. ACC 속도는 기준 원호 속도와 구분해 물리 속도를 사용한다.

최근 0.6초의 추정 속도에서 감속 추세가 관측되면 앞차의 느린 속도 경계를 낮춘다.
`leader_decel_horizon: 0.5`초, `leader_decel_limit: 1.5`m/s²로 최대 0.75m/s의
추가 감소를 반영한다. 트래커 속도를 다른 위치 회귀값으로 대체하지 않으며,
같은 센서 프레임을 반복 처리해 관측 이력을 늘리지 않는다.

COMMIT은 승인한 앞차/뒤차 ID를 유지한다. 차량이 누락되거나 틈 안에 새 차량이
나타나면 그 틈을 거부한다. 다른 틈의 GO로 기존 진입을 정당화하지 않는다.
기존 제동 가능 거리 및 취소 확인시간으로 양보 복귀 여부를 결정하고,
취소 후에는 실제 정지가 끝나야 재승인할 수 있다.

빌드와 단위 테스트 63개를 통과했다. `test/replay_entry_snapshots.py`와
`replay_entry_snapshot`으로 20:54:20 백의 기존 COMMIT 순간 10개를 재판정하면
1개는 추가 대기, 9개는 거부이며 즉시 출발은 0개다. 재판정은 기록된 차량 궤적과
반올림된 디버그 거리/속도를 사용하는 오프라인 검사다. 변경된 제어에 대한 NPC 반응과
실제 진입 완료 여부를 재현하는 폐루프 검증은 아니며, 다음 주행에서 확인해야 한다.
기존 ACC 감속을 포함하므로 촘촘한 흐름에서는 대기가 늘어날 수 있다.
새 로직과 YAML을 반영하려면 회전교차로 미션 노드를 재시작해야 한다.

## 2026-09-30: 통합 런치 설정과 출발 후 예측 보완

- `tuning_perception.yaml`은 site YAML보다 나중에 로드된다. 통합 파일에도
  속도 창 20개/1.8초, 최소 관측 0.3초, EMA 0.25, 차량 최대 길이 14m/높이 4.5m,
  확정 차량 보존 3초를 명시한다. 개별 tracker launch도 이 통합 설정을 로드한다.
- 원형 속도 추정은 관측 크기 차이가 `velocity_extent_tolerance`(기본 0.5m)
  이내인 실제 관측 쌍만 사용한다. 쌍의 끝 관측은 최근 0.4초 안이어야 한다.
  보이는 면이 바뀌며 중심점이 이동한 구간의 기울기가 속도로 섞이는 것을 줄인다.
  비교 가능한 관측이 없으면 속도 유효성을 내리고, 실제 정지 관측은 별도로 반영한다.
  크기 변화 없이 중심점만 변하는 경우는 기존 중앙값 추정으로 완화하며 완전한 제거를
  보장하지 않는다. NPC 설정 속도는 추정값으로 사용하지 않는다.
- COMMIT에서는 현재 위치와 속도로 도착 시간을 이어 계산하고, 출발 거리 게이트와
  최초 반응 지연을 재적용하지 않는다. 앞차가 아직 합류 구역을 점유하면 합류 구역 앞에서
  정지·대기한 뒤 재출발하는 보수적인 예측을 사용한다. 뒤차 TTC/간격 검사와 진입 취소는 유지한다.
- MPC 피팅과 앞뒤 안전 임계값은 변경하지 않는다. 빌드/단위 테스트 및
  `roslaunch --dump-params`로 설정 우선순위를 확인하며 백 재생은 하지 않는다.
