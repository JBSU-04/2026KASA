# M8 점유 형상 통일과 지도 분류 C++ 전환

적용 범위는 음영구간 M8이다. MPC 설정, 기존 전진/후진 엔진, 측위 구조,
다른 미션의 판단, 기준경로 코리도와 속도 설정은 변경하지 않는다.
백 재생이나 현재 주행 런치 재시작 없이 소스·빌드·단위 검증을 수행했다.
실제 통과와 제어 성능은 다음 MORAI 주행에서 확인해야 한다.

## 적용 동작

- GPS 빈 터널 지도 `tunnel_static_gps_20261009.npz`는 보존한다.
  `.bin`은 동일한 원점·float32 점들을 무손실로 포장한 C++ 입력이다.
  도로/벽을 추가 생성하거나 랜덤 장애물을 지도에 학습시키지 않는다.
- 분류 노드는 기본 C++이다. 원래 Python 노드는 복귀용으로 남긴다.
  최신 스캔 하나만 대기시키고 지도 검색 구조를 시작 시 구축한다.
  배경 판정은 기존 3D 거리 문턱 안의 점 존재 여부를 검사하며,
  노면은 1.2m 이내 정확한 최근접 3점과 기존 높이 편차 조건을 사용한다.
  원시 점을 사전 다운샘플링하지 않는다.
- 기존 중력 정렬 점군과 스캔 시각 odometry를 사용한다. 시각 간격과
  만료 조건을 유지하며, X-ICP XY 보정은 배경 검색에만 적용한다.
  장애물 이동 좌표에는 보정을 중복 적용하지 않는다.
- 저상 후보 0.08m, 3점, 서로 다른 2스캔, 배경 거리 0.12m,
  노면 일치 거리 0.055m, 분류 만료 0.35초는 유지한다.
- M8 계획·탈출은 실제 점유 셀을 검사한다. 정지 노드는 물체별로
  귀속된 동일 셀을 검사한다. 큰 보존 상자는 검색/표시용이며,
  물체 사이의 빈 공간을 볼록 외곽으로 채우지 않는다.
- 점유가 사라져도 이를 곧바로 빈 공간으로 판정하지 않는다.
  엔진의 서로 다른 3스캔 광선 확인으로 제거된 고정 점유에만
  `measured_ray_cleared_world`를 발행한다. 일시 점유의 만료, 가림,
  지도 범위 이탈은 정지 해제 증거가 아니다.
- 실제 차체와 앞으로 이동할 차체 영역을 물체별 점유로 검사한다.
  다른 물체의 충돌 셀로 해당 물체의 handoff guard를 유지하지 않는다.
  신선한 안전 경로가 해당 물체를 통과하지 않으면 guard를 해제하고,
  센서/경로/형상 정보 부족 및 실제 충돌 위험은 유지한다.
- 동적 승격은 신선한 독립 관측 2스캔, 속도·이동 방향, 관측 형상과
  양쪽 표면의 일관된 이동을 요구한다. 정적 부모의 상자 성장만으로
  `world_fast` 또는 배경 이동 분기를 우회할 수 없다.
  움직임 미확정 물체의 기존 20m 선서행·6m/s 제한은 유지한다.
- M8 유지 경로는 현재 위치·헤딩에서 연결한 경로도 검사한다.
  최종 발행 노드가 동일 plan_id를 occupancy/곡률/충돌/경계/연결 실패로
  거부하면 기존 유지 경로를 해제하고 정지 후 현재 자세에서 재계획한다.
  다른 계획 ID의 지연된 거부는 적용하지 않는다.
- 차체 폭·길이, 장애물 여유 0.2m, 벽 여유 0.1m,
  추종 오차 0.3m·10도 기준은 유지한다.

## 진단과 RViz

- `/tunnel/map_state`: backend, map_version, 원본 스캔 시각, compute_ms,
  배경/후보/확정/노면 미확인 개수, 정합 나이와 검색 보정량.
- `/tunnel/static_map`: 실제 활성 GPS 3D 배경 지도. 현재 위치 주변만
  1Hz로 표시한다. 표시용 축소는 분류용 원본 지도에 영향을 주지 않는다.
- 기존 `/tunnel/bg_map`은 이전 2D 지도라고 표시하고 기본 화면에서 끈다.
- `/tunnel/map_background`와 `/tunnel/map_foreground`는 제거점/잔차점이다.
- `/occupancy_avoidance/markers`: 최근 관측 고정 점유는 빨강,
  가림으로 보존한 고정 점유는 보라, 일시 점유는 주황으로 구분한다.
  확인 가능한 충돌 셀은 빨간 구로 표시한다.
- `/obstacle_info`: 물체별 occupied_cells_world와 형상 시각·유효성·사유.
- 정지 진단에는 동적 승격 근거가 포함된다. 엔진 후보 상태에는
  plan_id, 추종 오차, replan_pending, geometry_stamp가 포함된다.
  셀과 추적 ID가 연결되지 않은 엔진 충돌은 ID -1로 표시한다.

## 검증 결과와 실주행 확인

Python 283개, C++ 81개 단위 검증이 통과했다. 빌드 및 단위 검증 로그는
`analysis/m8_unified_20261009/`에 보관했다.
합성 33,504점, 실제 지도, 30회 분류+확인 커널 측정은 p50 약 46ms,
p95 약 49ms였다. ROS 직렬화·정합 검색·전체 런치 경합을 포함한 수치가
아니므로 전체 주행 p95 80ms 충족으로 해석하지 않는다.

다음 주행에서는 빈 터널 구조물 오정지, S자 통로의 점유 형상,
연결 실패 후 재계획, 옆 물체의 guard 해제, 20m에서 충분한 점이 있는
물체의 두 번째 확인 스캔 이후 선서행 0.25초 내 발행을 확인한다.
실제 통로가 없는 경우와 정보가 부족한 경우의 정지는 유지한다.

## 복귀 설정

지도 분류만 복귀하려면 기존 대회 런치 명령에 다음 인자를 추가한다.

```bash
roslaunch total_bringup competition.launch tunnel_map_backend:=python
```

새 M8 셀/동적 정책만 복귀하려면
`new_lane/config/tunnel_recovery.yaml`의 다음 값을 false로 바꾸고 재시작한다.

```yaml
obstacle_info_merger:
  tunnel_cells_authoritative_enabled: false
obstacle_stop_node:
  tunnel_cells_authoritative_enabled: false
  tunnel_motion_evidence_enabled: false
obstacle_avoidance_node:
  embedded_engine:
    tunnel_cells_authoritative_enabled: false
```

그 외 기존 tunnel_replan/integrated_escape/swept_guard 설정은 그대로 둔다.
전체 변경 전 원본은 `backups/m8_unified_20261009/source_before.tar.gz`,
런치 원본은 `launch_before.tar.gz`, `planning_launch_before.tar.gz`에 있다.
MPC 11개 설정 파일의 사전 해시는 `mpc_hashes.json`에 보관했다.

새 NPZ를 만들었을 때만 동일 지도 포장 명령을 사용한다.

```bash
rosrun new_lane export_tunnel_runtime_map.py SOURCE.npz TARGET.bin
```

C++ 지도 경로는 `new_lane/launch/obstacle_avoidance.launch`의
`tunnel_static_map_binary`에서 선택한다. NPZ와 bin은 같은 지도를 사용해야 한다.

## 오픈소스 출처

기존에 보존한 Autoware compare-map 원본의 커밋과 파일 해시는
`new_lane/vendor/autoware_compare_map/UPSTREAM.json`에 있다
(commit `dc1fcea1d7ccae851466e7c4db3843c08304c6a5`, Apache-2.0).
이번 C++ 노드는 그 3D 거리 판정과 기존 ROS1 어댑터를 바탕으로 작성했으며,
ROS2 원본 노드를 직접 실행하는 방식은 아니다. 노면 검증, 독립 스캔 확인,
최신 입력 처리, 로컬 노면 검색, 점유 귀속은 우리 미션용 추가 사항이다.
원본 파일과 라이선스는 변경하지 않았다.
