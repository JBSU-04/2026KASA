# 터널 배경 이동 후보의 정적 검증

`obstacle_stop_node`에서 `/tunnel/bg_moving` 후보를 정지 판단 및 일반 트랙의
동적 승격에 사용하기 전에, 같은 위치의 신선한 일반 트랙 관측과 대조한다.
배경 검출 자체와 정적 회피용 장애물은 제거하지 않는다.

- 기존 매칭 반경 1.5 m 안에서 가장 가까운 일반 트랙을 사용한다. 가까운 두
  후보의 거리 차가 0.3 m 미만이면 매칭이 애매하므로 기존 정지 판단을 유지한다.
- `last_seen`과 `observation_age`가 모두 0.3 s 이내여야 한다. 원거리 정적
  제안(`raw_temporal_far`), 인프라 후보, 지나간 트랙은 정적 검증 근거가 아니다.
- 최근 실측 위치의 0.3/0.5 s 평균 속도와 약 1 s 이동량을 확인한다.
  원거리 정적 자리와 일치하면서 이동 < 0.8 m, 두 속도 < 0.6 m/s이거나,
  confirmed 트랙이 0.8 s 이상 정지하고 두 속도 < 0.3 m/s, 이동 < 0.25 m이면
  배경 후보를 정지/동적 승격 근거에서 제외한다.
- 단, 최근 0.4/0.8 s 창에서 실측 3개 이상, 관측 기간 0.25 s 이상,
  순이동 0.25 m 이상, 평균 0.3 m/s 이상이며 앞/뒤 이동이 같은 방향으로
  일관되면 정적 이력보다 새 이동을 우선한다. 같은 측정의 반복 발행은
  위치 이력을 추가하지 않는다. 단일 중심점 점프는 일관된 이동이 아니다.
- 매칭 실패, 가림/오래된 관측, 이력 부족이면 기존 배경 정지 판단을 유지한다.

파라미터: `tunnel_bg_static_validation_enabled=true`,
`tunnel_bg_static_fresh_sec=0.3` (`launch/obstacle_stop.launch`).
제외 로그: `배경 이동 후보 정적 검증 제외: bg_id=... (bg_matched_static_id_...)`.

위치 기반 매칭이므로 가까운 별개 물체가 같은 물체로 매칭될 위험은 남는다.
움직임 검증에 여러 실측이 필요하므로 실제 이동 시작 직후의 판단 지연도
없다고 보장할 수 없다. 정지 거리/코리도, 정지 유지 시간, 회피 방향 유지
로직은 이번 변경에서 조정하지 않았다.

ROS master와 제어 노드 실행 없이 테스트:

```sh
/usr/bin/python3 src/new_lane/test/test_background_static_validation.py
```

백 재생 및 실차 검증은 수행하지 않았다.
